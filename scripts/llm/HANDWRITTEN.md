# 手書き会話 ― 書くときの決まり

`programs.jsonl` の約半分（`is_templated(id) == False` の側、約2000本）には、phrasebank の合成では
なく**手で書いた会話**を付ける。その作業の仕様書。

## 0. なぜ手で書くのか

**定型句や慣用表現では作れない多様性を生み出すため。**

合成は語彙表の直積しか書けない。慣用句表はその穴を埋めるが、表に載せた言い方しか出てこない。
どちらも**有限の言い方を厚くする**装置であって、言い方そのものを増やせない。

一度失敗している。前回は「1プログラム＝1指示文」で2036本書き、`parse_instruction.py` の
レキシコンで検査を通すよう直させた。結果は合成側の分布のコピーで、文末「〜ください」が19%、
「〜て、〜て」連結が52%、言い直しは0.3%しか無かった。**読めるように書いた文は、合成と同じ文**。
だから検査で言い回しを縛らない。

## 1. 単位と入出力

**単位は1会話。単発（1ターンだけ）は書かない。**

```
入力  programs.jsonl の 10行     {"id": "s0-000123", "program": [...]}
出力  handwritten.jsonl の 10行  dataset.jsonl と同じ行の形（下記）
```

```json
{"id": "s0-000123", "category": "handwritten", "style": "kansai",
 "turns": [
   {"role": "user", "content": "<人の発話>", "queue": []},
   {"role": "assistant", "reply": "<返事1文>", "program": [<この発話のあとのキュー全体>]},
   {"role": "user", "content": "<人の発話>", "queue": [<いまロボットがやってる残り>]},
   {"role": "assistant", "reply": "<返事1文>", "program": [...]}
 ]}
```

- `id` は元のものをそのまま。`split` は書かない（`build_dataset.py` が id から決める）。
- 渡されたプログラムは**1ターン目で頼む内容**。2ターン目以降は自由に続ける。
- 2〜5ターン。会話の長さもばらす。

## 2. queue と program ― ここだけは厳密に

`queue` は**その発話の瞬間にロボットが持っている手順**。`program` は**その発話のあと
ロボットが持つ手順の全体**（差分ではない）。システムプロンプトの規則そのまま:

| 人の発話 | 返す program |
|---|---|
| 止めて | `[]` |
| 今すぐ〜して（走行は続ける） | `[新しい手順, queueの中身...]` |
| 終わったら〜も | `[queueの中身..., 新しい手順]` |
| やっぱり〜（差し替え） | 新しいリスト |
| 雑談・質問・提案 | `queue` をそのままコピー |

- 1ターン目の `queue` は必ず `[]`（立ち止まった状態から始まる）。
- 2ターン目以降の `queue` は、直前の `program` の**途中から先**。途中で喋りかけたなら
  先頭の手順の量だけ減る（`5m進む` の途中なら `{"distance_m": 1.8}`）。
- **長さの無い `move` / `stance` の後ろには何も置けない**（止まるまで走り続けるので「そのあと」が
  無い）。長さ無しは必ずリストの最後。
- 走り技（直前が `move` の `flip`）は、その move の向きと合う種類だけ:
  forward→frontflip / backward→backflip / left→sideflip_left / right→sideflip_right。

## 3. 返事

1〜2文。相手の口調に合わせる。`program` の中身（JSON・数字の羅列）は返事に書かない。
技の呼び名は**人が言った呼び名に合わせる** ―「宙返り」と言われたら返事も「宙返り」。

**ロボットは自分の実行結果・成否・得手不得手を語らない。** 「きれいに降りられました」「着地は決まりました」
「その動きは苦手で転ぶことがあります」はすべて捏造 ― この系にロボットが結果を知る経路は無いし、
できるかどうかは**ポリシーの責任**で、LLM は翻訳に徹する。所要時間・距離の見積もり（「10秒で終わるで」）も
コンパイラの仕事なので書かない。だから**そう答えるしかない質問を人に言わせない**。
人に言わせてよいのは、これから何をするか・手順の中身・世界の側の事情（「そこ壁や」）まで。

## 4. 広げたい軸 ― ノルマ

10本のバッチごとに指定される。目安は全体で:

| 軸 | 合成が書けているもの | 手書きで足すもの | 目標 |
|---|---|---|---|
| 語順 | 修飾→動詞 | 動詞先行、目的語後置、倒置 | 20% |
| 助詞 | 正しく全部 | 落とす（前3m行って / 倒立5秒） | 20% |
| 前置き | なし | ねえ / あのさ / 悪いけど / そしたら | 15% |
| 後置き | なし | お願い / 頼むわ / いける? / よろしく | 15% |
| 言い直し | なし | 「前に…いや、後ろに3m」 ※最終的な手順だけが program と一致 | 15% |
| 表記ゆれ | m / メートル | ｍ、メーター、３ｍ（全角）、0.5m と 50cm | 15% |
| 長さ | 24字前後 | 5字以下と60字超の両端を厚く | 各10% |
| 同一文末 | ― | どの語尾も全体の5%を超えない | ― |

会話の2ターン目以降が口語の本体。ここが薄いと前回の失敗を繰り返す:

```
止める     もうええって / ストップ / はいそこまで / わー待って待って
割り込み   今!バク転! / あ、そこで倒立して
追加       それ終わったらバク転も / ついでに最後に一周
訂正       あ、ちゃうちゃう逆 / やっぱなしで / さっきの無し、右に変更
参照       さっきのやつもっかい / いまのまた / もう一丁
雑談・質問 それ何秒かかんの? / 疲れへん? / ええやん今の
```

## 5. やってはいけないこと

- **慣用句セットの丸写し**。`phrasebank.py` の表はもう合成側が使っている。表に**無い**言い方を書く。
- 機械的な言い換えの羅列（「前に3m進んで」「前へ3m進んで」「3m前に進んで」…）。合成の仕事。
- バッチ内で同じ語尾・同じ前置きを繰り返す。
- 返事に program を書く。数字を並べて確認するのも不可。

## 6. 検査は書きながらやらない

**書く工程では検査を一切走らせない。** 出すのは生の出力。検査は全部書き終わってからの別工程。

前回の失敗は、検査を書く工程の中に置いたことそのものやった。ツールが赤を出すと人は通る文に書き換える。
通る文＝そのツールの語彙で書かれた文＝合成側の文。構造検査でも同じことが起きる ― 弾かれない
プログラムばかり選んで書くようになり、走行中のキューや終わりのない move といった**状況の多様性**が痩せる。

あとから走らせるもの:

```
構造   python scripts/llm/check_handwritten.py <ファイル>
       行の形・program の文法・queue の連続性だけ。日本語は読まない。
       壊れの種類で分岐 ― 数値のズレは機械修正、意味が違うものは書き直しか破棄。
読み返し 別のエージェントが文だけを読んでプログラムを組み、元と突き合わせる。
```

## 7. 運用手順

`$JOB` は生成作業のスクラッチ置き場。`data/llm/` に出すのは**人が見て採用したあと**だけ。

```
0. 入力            10本ずつのバッチに割り、バッチごとの要求特性を機械生成して添付する。
                   → $JOB/hw_in/batch_001.json … batch_204.json

1. 生成            エージェントに配る。検査は走らせない（§6）。
                   → $JOB/hw_out/batch_NNN.jsonl

2. 集める          cat $JOB/hw_out/batch_*.jsonl > data/llm/handwritten.jsonl

```

書く工程はここまで。`handwritten.jsonl` は書く工程の成果物、`dataset.jsonl` は学習が食うもので、
**人のゲートはその境目**にある ― 集まったものを人が見て、納得してから `build_dataset.py` に進む。
集めるところまでは何度やり直してもよい。
