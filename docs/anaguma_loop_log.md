## ルール（ユーザー指定）

- **いじってよいのは報酬関数のみ** — `mdp/rewards.py` の報酬関数、報酬項の weight/params、報酬重みの curriculum。
- **触らない** — EFGCL assist の強度、助走帯（`base_velocity.ranges`）、env 数、iter 数、Net2Net の起点、
  その他タスク設定・学習ハイパーパラメータ。

## サイクル2で分かったこと（2026-09-15 01:45）

**目的関数の入れ替えが正解だった。** mujoco 実測で **0.987m → 1.266m（+28%）、着地 78% → 90%** と
両方が同時に良くなった。Isaac 側の内訳は離陸 v_x 1.32 → **2.17**（v_z は 1.31 で不動）で、
**伸びたのは配分ではなく v_x そのもの**。Go2 で「配分比は報酬では動かない」と3ループかけて分かったのと
同じ形だが、今回は目的関数自体を積 `2·v_x·v_z/g` に変えたので v_x を買いに行く動きが正しい方向に出た。

**成功条件まであと 2.7%**（1.266m / 目標1.3m）。着地90%・成立100%は既に条件を満たしている。
Isaac の距離が 0.844 でまだ右肩上がりなので、**報酬を足す前に同じ構成で伸ばし切る**（サイクル2b）。
転倒が 2.4% → 7.1% に上がっている点は要監視——着地が 70% を割ったら landing 系の報酬を戻す。
